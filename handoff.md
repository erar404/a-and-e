## Failed Attempts
- **What was tried**: Testing the mobile bottom-sheet CSS (`@media max-width:640px`) by calling `resize_window` on the claude-in-chrome browser tab to shrink it to phone width. — **Why it failed**: This browser tool's tab renders on a fixed virtual viewport (~1920×842) regardless of `resize_window` calls; `window.innerWidth`/`matchMedia` never actually dropped below 640px. Worked around by extracting the raw text of the `@media` block from the live CSS file via `fetch` + brace-matching and injecting it unwrapped into a `<style>` tag for visual testing.
- **What was tried**: Using `display:contents` on `.chat-menu` so its child buttons (notify/refresh/call-check/signout) would hoist directly into the `.chat-head` flex row on desktop, avoiding a wrapper box. — **Why it failed**: A genuine Chromium quirk — once ANY ancestor has `display:contents` anywhere in its cascade (even if overridden later by a more specific `display:flex`), a `position:fixed` descendant's `top:auto; bottom:0` box resolves to a bogus "hypothetical static position" instead of anchoring to the real viewport bottom, landing the bottom sheet near the page top. Confirmed via an isolated clean-room test page (no `display:contents` anywhere) that the same `position:fixed;bottom:0;transform:translateY(100%)` pattern works perfectly on a fresh load. Fixed by replacing `display:contents` with a plain nested `display:flex; gap:1rem` wrapper (visually identical on desktop, no bug).
- **What was tried**: Debugging why `setChatSkinPlaceholder()` seemingly didn't swap the composer placeholder on repeated manual tests via the browser tool. — **Why it failed** (false alarm, not a real bug): `sessionStorage.vdiDisguiseOn` was persisting across my repeated `navigate()` calls within the same tab, causing the disguise to auto-resume on page load (in the pre-login overlay state, before my test script had set `chat.hidden=false`), so my subsequent "activate" click was actually a "deactivate" click. Confirmed the real logic works correctly once `sessionStorage.clear()` was called before each fresh test.
- **What was tried**: A center-aligned, narrow-column mobile-sheet mockup for early visual verification (before finding the `display:contents` bug), using `left:50%; transform:translate(-50%,100%)`. — **Why it failed**: Wasn't a failure per se, just a throwaway test artifact that didn't match production CSS (`left:0;right:0`, true full-width sheet) — caused confusing intermediate screenshots. Not shipped; noted here only so a future session doesn't mistake it for the real design.
